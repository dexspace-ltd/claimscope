# Decisions log

## Made

| ID | Decision | Why |
|---|---|---|
| A1 | AWS serverless in `eu-west-2`: S3, CloudFront, API Gateway HTTP API, Lambda (Python 3.12), Step Functions, DynamoDB | UK hosting promised; near-zero idle cost; matches proposal |
| A2 | Claude `claude-opus-5-5` for both AI stages, adaptive thinking, structured outputs | Strongest vision and judgement; structured outputs remove JSON parsing failures |
| A3 | LLM selects items and a quantity basis; deterministic engine computes quantities and prices | Auditable £, no hallucinated prices, fixes unit-confusion errors |
| A4 | Catalogue mirrors insurer schedule operations (supply / fit / take up / remove-set-aside-refit / prelim) | Output reads like the schedules insurers already accept |
| A5 | Materials from permitted retail sources only; labour = minutes × client-set trade rates | Defensible and editable; no retailer-terms risk |
| A6 | Infra as code with AWS CDK (Python) | One language across backend and infra |
| A7 | Hosted platform, client gets admin access; proposal says nothing about IP ownership | Commercial direction from founder, 11 Oct 2026 |
| A8 | Demo orchestration: API Lambda invokes a pipeline Lambda asynchronously (15 min timeout, no auto-retry); browser polls status. Step Functions deferred | API Gateway caps requests at 30 s, so analysis must be async either way. Estimated run with parallel model calls is ~3–8 min (30 photos, 5 rooms), inside 15 min; sequential would not be. Stages are plain functions, so moving to Step Functions is a wiring change if measured runs approach the limit |
| A9 | Demo front end is plain HTML/CSS/JS on S3 + CloudFront, no build step. Revisit React when the review screen (week 3) needs it | Fastest path to a working demo |
| A10 | Every line is approved by the assessor before submission; the AI only drafts | Assessor remains accountable; confirmed by founder 11 Oct 2026 |
| A11 | Default scan capture needs no Matterport SDK: the public tour is embedded as a plain iframe and the browser's tab-sharing permission grabs views while the assessor walks each room (auto-kept when the camera settles on a new view). The SDK auto-walk remains as an option where a key works | Matterport SDK production keys need a paid plan plus an add-on fee; free sandbox keys work on localhost only (Matterport help centre, updated 9 Oct 2026). Tab capture is equivalent to the assessor taking screenshots of what they are viewing; it does not automate Matterport's viewer |
| A12 | Rooms and dimensions come from one capture of the tour's floor plan view, read by Claude (labelled → scaled → estimated, recorded per room). Heights default to 2.4 m. Assessor edits any room inline | Removes manual measuring for the demo; the source of each dimension is visible so estimates are not mistaken for measurements |
| A14 | Auto-walk without the SDK: the page reloads the embedded public tour at each scan point with `ss=<n>&sr=<pitch>,<yaw>` (verified on Matterport's public sample, 12 Oct 2026: negative pitch looks down; an out-of-range `ss` falls back to the start view, which marks the end). Four views per scan point, two tours in parallel, captured via tab sharing. Claude assigns each view to a floor-plan room (majority per scan point) or, without a floor plan, creates rooms from its room-type guesses with estimated sizes | Removes the manual walk. Undocumented URL behaviour can change without notice, and automated use of the viewer sharpens the open terms question in D5 |
| A15 | Each captured view is analysed (Stage A) as soon as it lands in S3, by an S3-triggered Lambda capped at 8 concurrent runs; findings are stored on the evidence record. Drafting reads stored findings, so a re-draft only re-runs room itemisation. A new auto-walk replaces the previous walk's views. The walk runs in a docked corner panel, not full screen | Measured run (12 Oct): 136 views = $3.16 of $3.55, half of it a duplicate walk; re-drafts repeated it. Tab capture still needs the tab visible, so fully server-side capture would mean a headless browser driving Matterport's viewer, which is slower, fragile and a sharper terms question |
| A16 | Captures are kept 30 days (demo) for evidence thumbnails on lines, re-analysis without re-walking, and the evaluation set | Storage cost is fractions of a penny per claim. Live claim data needs the retention agreed in the DPA |
| A17 | Demo limits: 2 new assessments per viewer IP per day (CloudFront viewer address, stored as a salted hash, counters expire after 2 days), 400 captured views and 5 drafts per assessment. The API only accepts requests carrying CloudFront's private origin header. Exempt IPs via `-c rateLimitExemptIps=<ip,...>` | Caps Claude spend on a public demo link. IP is the practical identifier: shared office or home networks share an allowance, and mobile networks change address |
| A18 | Demo report: printable A4 page on the Dexspace letterhead (logo, dexspacehq.com, business email; no phone on a public page), downloaded via the browser's print to PDF. Marked as an AI-assisted draft subject to assessor approval | Founder choice 12 Oct 2026. Production reports will follow the client's format (D6) |
| A19 | Incident brief (date of incident, date noticed, detail, cause, further info) is stored on the assessment and passed to every room's itemisation as authoritative site knowledge; lines it drives carry a `from_brief` flag. General items are rule-based and scaled (days on site from labour hours, skips from stripped floor area). Room types are a fixed list; guessed rooms are rebuilt on each draft. QA R06 checks continuous floors across rooms | Measured: property-wide coverage of the client's schedule rose from 17% to 52% of lines (66% of value) on the same views (`REPORT_FORMAT.md`) |
| A20 | Walkthrough videos with spoken commentary are a second evidence source, alone or alongside a Matterport tour. Upload to `videos/`; a video Lambda extracts the soundtrack (any container, including iPhone .MOV), transcribes it with Amazon Transcribe (en-GB, eu-west-2), picks about one sharp frame per new view (max 60), and Claude splits the timestamped commentary into rooms and drafts the incident brief (contents mentioned are listed for the contents claim). Frames go to per-view analysis with their room and only that room's commentary. A new video replaces the previous one's frames and rooms | Assessors already film walkthroughs; the commentary carries what the images cannot (cause, extent, repairs done). Claude takes images and text, not audio or video, hence transcription plus frames |
| A13 | Comparison with the original report runs locally (`tools/compare`), never uploaded. Output in `local/` (git-ignored) | Founder decision 12 Oct 2026: the original report is live claim data and the DPA is not signed |
